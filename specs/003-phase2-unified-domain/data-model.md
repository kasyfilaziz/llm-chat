# Data Model: Phase 2 Unified Domain

## SQLite Entities (Domain: `chat`)

### Table: `conversations`
Represents a chat thread history, supporting the sidebar UI.

- `id`: TEXT PRIMARY KEY (UUID v4)
- `title`: TEXT NOT NULL (Auto-generated by LLM, user editable)
- `created_at`: INTEGER NOT NULL (Unix timestamp)
- `updated_at`: INTEGER NOT NULL (Unix timestamp)

### Table: `messages` (Updates to Phase 1 Schema)
Links messages to their parent conversation.

- `id`: TEXT PRIMARY KEY
- `conversation_id`: TEXT NOT NULL (Foreign Key referencing `conversations.id`)
- `role`: TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system'))
- `content`: TEXT NOT NULL
- `created_at`: INTEGER NOT NULL

*Pagination/Infinite Scroll Mechanism*:
Queries on `messages` will use `ORDER BY created_at DESC LIMIT X OFFSET Y` to support chunked loading, minimizing memory bloat for massive histories.

## YAML Entities (Domain: `settings`)

### Struct: `AppSettings`
Persisted in `~/.config/lumina/settings.yaml` (or OS equivalent). Deserialized using `serde_yaml_ng`.

```yaml
provider_preferences:
  default_llm: "openai" | "ollama"
  openai_api_key: "<optional_key>" # If present, overrides .env
  ollama_endpoint: "http://localhost:11434"
mcp_servers:
  - name: "filesystem"
    path: "/usr/bin/npx"
    args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/workspace"]
  - name: "brave-search"
    path: "/usr/bin/npx"
    args: ["-y", "@modelcontextprotocol/server-brave-search"]
```
